## Findings

### 1-01 · Pressing a tool's number picks the next tool when that group is already on

- **Impact:** High — in every scene the first key press after the editor opens gives the wrong shape: pressing 1 to draw a box gives an ellipse.
- **Current experience:** The editor opens with "1 Box" already highlighted. Pressing 1, which the README describes as "Box", switches to "1 Ellipse". The same happens with 5: pressing 5 for a second numbered marker right after the first turns the tool into "Card", so the next click drops an empty card instead of marker 2. My own test script fell into both traps: it asked for a box and a second marker and got an ellipse and a card.
- **Visual:** `1-a-review.png` (toolbar reads "1 Ellipse" after one press of 1; marker 2 sits where a card was meant to go), `1-a-names.png` ("1 Box" already on at open).
- **Recommendation:** Make the key mean "pick this group" when the group is not what the user last chose on purpose, and "next tool" only on a quick repeat (for example, within about a second), or open with no tool picked. Keeps the owner's cycling and makes the first press predictable.
- **Tradeoff:** A time window is invisible; a user who pauses and presses again stays on the same tool. Alternative: the first press always selects the group's first tool, the second press cycles — simpler, but loses "last used tool per group".
- **Decision needed:** Should the first press of a number always give the group's first tool, with cycling only on a repeated press?
- **Verified:** seen on screen.
- **Owner's words:** "When I press the same button multiple times, let's say I have the 1 button, I would switch between the shapes and it would indicate it at the top." — 2026-09-25

### 1-02 · The meaning of each tool group ("Remove", "Approve", "Note") is hidden

- **Impact:** Medium — a reviewer in the quick-verdict scene sees "3 Cross" and "4 Tick", never "Remove" and "Approve", so the product's core idea (red goes, green stays) is not stated anywhere in the editor.
- **Current experience:** The toolbar shows the key and the current tool name: "1 Box", "2 Arrow", "3 Cross", "4 Tick", "5 Numbered", "6 Highlighter", "7 Cut & move", "V Select". The group names Mark, Draw, Remove, Approve, Note, Highlight and Move appear only in hover tooltips ("Remove: Cross → Crossed box → Remove area"). The README lists tools, not groups.
- **Visual:** `1-empty.png` toolbar; proposal `1-proposal-editor.png` (a small group name above each tool name).
- **Recommendation:** Show the group name as a small label on each toolbar button, above or before the tool name. It teaches the categories once and makes "3 = remove" memorable.
- **Tradeoff:** A wider toolbar at the 1180 px minimum; may need smaller type or dropping the dots.
- **Decision needed:** Should the toolbar show what each group means (Remove, Keep, Note…) as well as the current tool?
- **Verified:** seen on screen; tooltip text read in the code.
- **Owner's words:** "Also again, we need more elements to be clear about what should go away and what should not." — 2026-09-25

### 1-08 · Pointing marks can be drawn in the Remove red and the Approve green

- **Impact:** High — in the quick-verdict scene, and for the agent reading the image, a red box means "look here" while a red cross means "remove"; a green ellipse or marker next to a green tick reads as "keep". The default picker colour is the Remove red, so every box, ellipse, arrow, marker, card stripe and move outline is red unless changed.
- **Current experience:** The colour swatch starts at the same red as Remove. With it set to green, the box and the numbered marker come out the same green as the tick. With it set back, a box sits next to a cross in the identical red. The cut-and-move outline is a dashed red rectangle, which looks like a "remove area".
- **Visual:** `1-a-colour.png` (green ellipse and green marker beside a green tick; red ellipse beside a red cross), `1-a-review.png` (red dashed outline of the cut piece).
- **Recommendation:** Reserve red and green: pointing marks default to a neutral third colour (for example blue or magenta), and the picker offers a short palette that leaves out the Remove red and Approve green.
- **Tradeoff:** Less freedom of colour; the owner may like red for "look here".
- **Decision needed:** Should red and green be reserved for remove and approve, so no other mark can use them?
- **Verified:** seen on screen.
- **Owner's words:** "Also again, we need more elements to be clear about what should go away and what should not." — 2026-09-25; hard rule in setup: "Remove marks are always red and approve marks always green."
