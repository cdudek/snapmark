# Evaluator 7: independent heuristic evaluation of Snapmark v0.9.0

Every lens in `lenses.md` (Nielsen, Shneiderman, the six plain questions, Maze, the 30 Laws of UX,
writing and vocabulary) on the whole app. I started with the secondary scenes (sharing a session
as PDF or ZIP, a quick verdict) and the error paths (mis-pressed shortcuts, lost work, a missing
session, full-screen apps), then covered the main scene. I did not read the earlier audits, the
interaction guidelines, the sitemap, the glossary proposal, the decision logs or any other
evaluator's notes.

**How I looked.** The real editor and session window ran through the audit harness and through
my own driver script on the mock "Acme Ops" page, with a fresh temp `SNAPMARK_ROOT` each time
(screens `7-*.png`). Window sizes seen: the editor at 1180 × 600 at 2× and 1×, and 1920 × 1080
in dark mode (`7-editor-1920-dark.png`: the layout holds, the toolbar just gets smaller relative
to the canvas); the session window at 900 × 900, 900 × 700 and 560 × 480, light and dark. The
area picker ran through the harness. The menu bar menu was built from
its data for six states. The menu, macOS's capture overlay, notifications, native dialogs,
Spaces and first run cannot be scripted; those findings say "read in the code".

**Where the findings stand.** Findings 7-01 to 7-13 are the error paths, 7-14 to 7-18 sharing
with a person, 7-19 to 7-23 a quick verdict, and 7-24 onwards the main scene and the whole app.
The answers to the briefing's four questions come after the findings.

## Findings

### Error paths: mis-pressed keys, lost work, a missing session, full-screen apps

### 7-01 · A mis-pressed New Session quietly splits one review into two sessions

- **Impact:** High — a reviewer in the middle of an overnight review who hits `⌃⇧2` instead of `⌃⇧1` or `⌃⇧3` sends every later capture to a new, empty session without noticing, and the agent later gets only half the review.
- **Current experience:** `⌃⇧2` sits between the two capture keys. Pressed on a session that has screenshots, it makes a new session current at once; the only sign is a macOS notification, "New session: 2026-09-28 14.35", which disappears (and does not appear at all when notifications are off or a Focus is on). The next `⌃⇧1` opens the editor with "→ 2026-09-28 14.35" in small grey type in the top right corner. There is no Undo: going back means the menu, Switch Session, and recognising the old session by its timestamp. Screenshots already saved into the new session cannot be moved; the empty session stays in the list.
- **Visual:** `7-main-editor-annotated.png` — the grey "→ audit" in the corner is the only place the editor names the session it saves into. No screenshot of the notification (not scriptable).
- **Recommendation:** Take the global shortcut off New Session. Starting a session is rare (once per piece of work) and can wait for the menu; capturing is frequent and needs the keys. If a key is kept, give it a modifier the capture keys do not share (for example `⌃⌥⇧N`) and make the notification carry an "Undo" that switches back and removes the empty session. Either way, the editor should say plainly which session it saves into (see 7-25).
- **Tradeoff:** One more click for the rare moment a reviewer wants a fresh session mid-flow. Keeping a key with an Undo keeps speed but still relies on a notification the reviewer may not see.
- **Decision needed:** Should New Session keep a global shortcut at all?
- **Verified:** read in the code (the shortcut, the empty-session guard, the notification); the editor's corner label seen on screen.
- **Owner's words:** "Also the new session is a very dangerous shortcut because it sits in between 1 and 2." — 2026-09-28

- Other products: macOS Screenshot and CleanShot X have no "new project" key at all; Shottr keeps its global keys to capture modes.

</details>

### 7-02 · Snapmark's capture keys sit one modifier away from macOS's own screenshot keys, with different meanings

- **Impact:** Medium — a reviewer whose fingers know macOS Screenshot (`⌘⇧3`, `⌘⇧4`, `⌘⇧5`) and hits Command instead of Control, or the other way round, gets the other tool: a full-screen PNG on the Desktop instead of an editor, or a Snapmark capture instead of a quick macOS one.
- **Current experience:** Control and Command sit next to each other. `⌃⇧3` is "Capture Same Area" in Snapmark, `⌘⇧3` is "whole screen to Desktop" in macOS, and `⌃⇧⌘3` is "whole screen to clipboard". The digits also mean different things: in macOS 4 is "a region", in Snapmark 1 is. The owner uses macOS Screenshot.
- **Visual:** the keys side by side:

| Keys          | macOS Screenshot        | Snapmark v0.9.0                 |
| ------------- | ----------------------- | ------------------------------- |
| `⌘⇧3` / `⌃⇧3` | whole screen to Desktop | Capture Same Area               |
| `⌘⇧4` / `⌃⇧1` | a region                | a region ("Capture Screenshot") |
| `⌘⇧5`         | the capture toolbar     | nothing                         |

- **Recommendation:** Line the digits up with the meaning macOS gives them: region on `⌃⇧4`, same area on `⌃⇧5`, nothing on 3. Offer a way to change them (see 7-48).
- **Tradeoff:** Moving keys again right after the owner learnt `⌃⇧1`/`⌃⇧3`; lining up with macOS makes a Command/Control slip produce the same kind of capture, which is the point.
- **Decision needed:** Should Snapmark's region capture use the same digit as macOS's region capture (4)?
- **Verified:** read in the code; the macOS key meanings are the platform's defaults, not tested here.
- **Owner's words:** "3. The shortcut Command-1 on Chrome changes the tab. How about we do something different?" — 2026-09-28; "MacOsScreenshot, Figma, Ocra, Xnapper" — 2026-09-25

<details><summary>Supporting notes</summary>

- Where: global shortcuts.
- Broken: Jakob's law, Mental model; Nielsen 4 consistency and standards (platform), 5 error prevention.
- Code: `src/main.ts:30-33`.
- Other products: CleanShot X can take over the `⌘⇧3/4/5` keys; Shottr and Xnapper use their own combinations and let you change them.

### 7-03 · A third Esc throws the screenshot away, notes and all

- **Impact:** Medium — a reviewer who presses Esc a few times to "get out" of a note or a tool closes the editor and loses the screenshot from view; it comes back only through the menu bar.
- **Current experience:** Measured on the real editor: place a reference, type "Header too tall", press Esc. The first Esc leaves the note, the second switches to Select, the third closes the window. Nothing asks, nothing says where the screenshot went. The Keyboard Shortcuts window documents it: "out of the text, then deselect, then back to Select, then close".
- **Visual:** `7-keyboard-shortcuts-full-annotated.png` (the Esc row). The closing itself cannot be pictured: the window is gone.
- **Recommendation:** Stop Esc at Select. Closing stays on `⌘W`, the close button and Discard, which are deliberate. If Esc must close, let it close only an editor with no marks and no text.
- **Tradeoff:** One extra key (`⌘W`) to throw away an unwanted capture, which is also the macOS way to close a window.
- **Decision needed:** Should Esc ever close the editor?
- **Verified:** seen on screen (driver: three Esc presses, window gone, one entry in Discarded).
- **Owner's words:** "I should be getting out of this mode by pressing Escape or something." — 2026-09-25; "I just wonder if we should introduce a shortcut with Escape and be able to recover it so nothing ever gets lost." — 2026-09-25

### 7-05 · Typing in the session window is lost when session.md changes at the same moment

- **Impact:** High — the reviewer's own words disappear from the file and from the window, with no message, when an agent, a sync client or the editor writes session.md while the reviewer is typing.
- **Current experience:** Measured: in the Document tab I typed " TYPED-BY-OWNER" at the end of an entry while an outside process appended one line to session.md. 1.5 s later the typed words were in neither the file nor the window; the window had reloaded the outside version. The control run without the outside write kept them. The window saves 200 ms after typing, refuses the save when the file changed under it, then reloads.
- **Visual:** `7-main-viewer-doc-annotated.png`.
- **Recommendation:** When the file changed under unsaved typing, keep the typing: merge it (an outside change is usually an appended entry), or keep the window's text and say so in the window ("session.md changed outside. Your edits are kept here.").
- **Tradeoff:** Merging is real work; a message is simpler but interrupts.
- **Decision needed:** Routine fix: no individual decision needed.
- **Verified:** seen on screen (driver, with a control run).
- **Owner's words:** "Also a full markdown view would be nice. including ideally editable like notion with markdown wyiwyg" — 2026-09-25

### 7-07 · From a full-screen browser, the editor takes the reviewer to the desktop and leaves them there; the next Capture Same Area then photographs the desktop

- **Impact:** High — with the owner's usual setup (a full-screen browser) every capture is a trip away from the page and back, and Capture Same Area captures the wrong Space from the second press on.

After "Add to session" the editor closes and the reviewer is still on the desktop. `⌃⇧3` then photographs the same rectangle of the desktop, because the browser is on another Space. The area picker, by contrast, is already set to show over full-screen apps.
- **Visual:** not capturable here (Spaces cannot be scripted).

- **Decision needed:** Routine fix: no individual decision needed (the owner already asked for the fix).
- **Verified:** read in the code and the owner's report; not reproduced.
- **Owner's words:** "When I take a screenshot it's going to the desktop but the actual window stays at the full screen browser. This is something we should fix." — 2026-09-28

## Answers to the briefing's four questions

### 1. New Session on `⌃⇧2`

- **What a mis-press costs.** When the current session already has screenshots, one press makes a
  new, empty session current with no confirmation and no Undo (7-01). The only feedback is a
  macOS notification that can be missed or suppressed (7-44); the editor names the session only in
  small grey type and the window title says just "Snapmark" (7-25). Every capture after it lands
  in the new session, so the agent gets half the review from Copy Prompt for AI. Recovery: menu →
  Switch Session → recognise the old session by timestamp (7-36); captures already saved in the
  new one cannot be moved; the empty session stays behind. When the current session is empty the
  press is harmless (the code refuses and says so).
- **Does it need a global key?** No. It is a once-per-piece-of-work action; the keys are for what
  is done dozens of times an hour. Recommended: no global shortcut, New Session inside a
  "Sessions" submenu (7-01, 7-34). If the owner wants a key, it should not share the capture keys'
  modifier-and-digit pattern (for example `⌃⌥⇧N`), and its notification should carry an Undo. The
  capture keys themselves collide in meaning with macOS's `⌘⇧3/4` (7-02) and cannot be changed
  (7-48).

### 2. The menu

- **Counted from the menu data:** 11 top-level items with no session (5 disabled), 13 in the usual
  state (a session with screenshots, an area set), 15 with something discarded, 16 with an update
  waiting; 3 submenus (Export Session, Switch Session, Settings); 1 header. The reviewer's two
  daily jobs (capture, hand over) share the level with Rename, Show in Finder, New Session and
  Reopen Discarded… (7-34).
- **Which earn their place:** Capture Screenshot, Capture Same Area, Open Session, one copy item,
  Export. Everything about managing sessions (Switch, New, Rename, Show in Finder, Other…,
  Reopen Discarded…) belongs one level down. Keyboard Shortcuts is help, not a setting (7-38).
- **Copy Session Info with a Settings choice?** It would cut one item but add a hidden mode (the
  same item copies different things depending on a setting two levels deep). The cleaner cut:
  move the key to the marks into session.md, then one "Copy for AI" copies a one-line prompt with
  the path, and a bare path would do the same job (7-33). That also fixes the PDF and ZIP having
  no key for a person (7-14). Proposal: `7-proposal-menu.png` (10 items).

### 3. Capturing from a full-screen app

- **Capture region (`⌃⇧1`):** macOS's overlay appears over the full-screen app; the editor is a
  normal window, so macOS shows it on a desktop Space. After saving, the reviewer is left on the
  desktop and has to swipe back (7-07, owner's report; read in the code).
- **Capture Same Area (`⌃⇧3`):** the area picker is set to appear over full-screen apps, so the
  first choice works in place. The editor then behaves as above. From the second press on, if
  the reviewer is still on the desktop, the fixed rectangle photographs the desktop, not the
  browser (7-07); if an editor is still open, it photographs the editor (7-06).
- **Fix direction:** open the editor over the Space the capture came from (the picker already
  does this), give focus back to the app that was in front after saving, and hide Snapmark's
  windows during a capture. All of this needs checking on a real full-screen browser.
