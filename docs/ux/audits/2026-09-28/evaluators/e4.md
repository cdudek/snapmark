# Agent 4 · Words, vocabulary, keys, earlier requests

Snapmark v0.9.0 (`main`), audited 2026-09-28. Checks C11 (writing for the audience), C12 (one vocabulary),
C15 (every earlier request re-checked), C17 (the keyboard); rule areas keyboard and focus, and platform
conventions; checklist "Content and microcopy". Owner of briefing question 1 (New Session on ⌃⇧2) and, with
agent 1, the words side of question 2 (one "Copy Session Info").

**How the evidence was gathered.** The editor, the session window and the area picker were opened on mock pages
through `AUD/harness.js` and three probe scripts of my own that load the app's compiled code with a temp
`SNAPMARK_ROOT` (never the real screen, sessions, clipboard or state). The probes read window titles, the exact
copied prompt (`promptFor`), rendered the Keyboard Shortcuts window from the app's own compiled
`showShortcuts()`, pressed View → Reload on an editor with marks, and called the menu role Edit → Undo. The menu
bar menu was printed from `dist/src/menu.js` for four states. Electron's default application menu was dumped
from Electron 44.4.5. Notifications, native dialogs and global shortcuts cannot be scripted: those findings say
"read in the code".

Screenshots: `../shots/4-*.png`. Annotated versions end in `-annotated`; the two sketches labelled
"PROPOSAL" are `4-proposal-*.png`.

# Findings

## Question 1 · New Session on ⌃⇧2

### 4-01 · New Session sits on ⌃⇧2, between the two capture keys, so a slip starts a new session

- **Impact:** High — in the main scene the reviewer presses ⌃⇧1 or ⌃⇧3 dozens of times a session; a finger one
  key off starts a new session, the capture they wanted never happens, and every later capture lands in the new
  session, so the review is split across two files and the agent is handed half of it.
- **Current experience:** ⌃⇧1 is Capture Screenshot, ⌃⇧3 is Capture Same Area, and the key between them, ⌃⇧2, is
  New Session. With screenshots in the current session, ⌃⇧2 creates "2026-09-28 14.40", makes it current and
  shows one notification, "New session: 2026-09-28 14.40". Nothing is captured. The next ⌃⇧1 opens the editor
  with "→ 2026-09-28 14.40" in its corner, "Add to session" files it there, and Copy Prompt for AI now points at
  the new, nearly empty session.
- **Visual:** `4-shortcuts-window-annotated.png` (the app's own list: ⌃⇧1 Capture region, ⌃⇧3 Capture same area,
  ⌃⇧2 New session). Proposal: `4-proposal-new-session-keys.png`.
- **Recommendation:** Take New Session off the capture row. Leave ⌃⇧2 unassigned, so a slip between the two
  captures does nothing at all; keep ⌃⇧1 and ⌃⇧3 exactly as they are (nothing to relearn); and give New Session
  either no global key (menu only) or ⌃⇧N, away from the digits. Starting a session happens once per piece of
  work; capturing happens many times a minute, and the rare, state-changing action should never be the easiest
  one to hit by accident. Pair it with 4-02 and 4-03 so any new session, wanted or not, is visible and reversible.
- **Tradeoff:** Menu only costs two clicks when starting new work and bends the rule "everything on the fly with
  shortcuts"; ⌃⇧N takes that combination from every other app while Snapmark runs, and is one more key to learn.
  Alternatives, each meaningfully different:
  - ⌃⇧1 Capture, ⌃⇧2 Capture Same Area, New Session elsewhere: the two captures side by side, where a slip costs
    one Esc. Costs relearning ⌃⇧3 a day after it shipped.
  - Keep ⌃⇧2 but make it a double press ("Press ⌃⇧2 again to start a new session"): safe, but an invisible mode
    and slower when meant.
  - Keep ⌃⇧2 and only add the way back (4-03): the cheapest change; every slip still loses the capture and
    costs a detour through the menu.
- **Decision needed:** Should New Session keep a global shortcut at all, and if it does, ⌃⇧N instead of ⌃⇧2?
- **Verified:** read in the code (global shortcuts are not pressed in this audit); the editor's destination
  label seen on screen (`4-editor-strings.png`).
- **Owner's words:** "Also the new session is a very dangerous shortcut because it sits in between 1 and 2."
  — 2026-09-28. "This is also important: when I create, as I said, it needs to be shortcuts so I can just do this
  on the fly." — 2026-09-25

### 4-02 · The editor names where a screenshot goes only as "→" and a folder name

- **Impact:** Medium — after a new session, wanted or not, nothing that stays on screen says the captures now go
  somewhere else: the notification disappears in seconds (or never shows with Focus on), and the editor's
  corner reads "→ 2026-09-28 14.40", a date the reviewer does not recognise as "a different, new session".
- **Current experience:** The top right of the editor shows "→ audit" or "→ 2026-09-28 14.32": an arrow and the

  nothing marking a session that has no screenshots yet.
- **Visual:** `4-editor-strings-annotated.png` (box on "→ audit"). Proposal: the bottom lines of

- **Decision needed:** Should the editor say "Adding to: <session> · new" and let you change the session before

## Question 2 · "Copy Prompt for AI", "Copy session.md Path" and "Copy session info"

### 4-05 · Two copy items, and neither label says that the prompt already holds the path

- **Impact:** Medium — every hand-off to an agent asks the reviewer to choose between "Copy Prompt for AI" and
  "Copy session.md Path", and nothing in the menu says the prompt begins with that very path; the owner has asked
  twice what gets copied.
- **Current experience:** "Copy Prompt for AI" copies 15 lines: `Work through the visual feedback in
"/Users/…/Snapmark/2026-09-28 14.32/session.md".`, one line on reading an entry, "What the marks mean:" and one
  line for each of the 12 tools. "Copy session.md Path" copies only `/Users/…/Snapmark/2026-09-28 14.32/session.md`,
  without quotes. The notifications say "Prompt for 28 Sep 14.32 copied. Paste it into your AI agent." and "Path to
  28 Sep 14.32 copied."
- **Visual:** Proposal: `4-proposal-copy-item.png`.

  | Where                | Before                                                         | After                                                                                 |
  | -------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
  | Menu                 | "Copy Prompt for AI" · "Copy session.md Path"                  | "Copy Prompt for AI", sublabel "path + what the marks mean"                           |
  | Settings submenu     | —                                                              | "Copied Prompt ▸ ✓ Path and What the Marks Mean · Path Only"                          |
  | Menu, with Path Only | —                                                              | "Copy session.md Path" (the label follows the setting)                                |
  | Notification         | "Prompt for 28 Sep 14.32 copied. Paste it into your AI agent." | "Copied: the path to 28 Sep 14.32 and what the marks mean. Paste it into your agent." |

- **Recommendation:** One item. It keeps the name "Copy Prompt for AI", because "prompt" says what lands on the
  clipboard, and gains a sublabel naming its contents. The path-only copy moves to Settings, as the owner
  suggested, and the menu item's label changes with the setting, so the menu never hides what it copies. This
  takes one decision out of every hand-off and keeps both uses.
- **Tradeoff:** Someone who wants the full prompt one time and the bare path the next must switch the setting;
  Settings grows by one submenu. Alternatives:
  - The owner's "Copy Session Info" with a Settings choice: one item, but "Session Info" names neither content,
    and the label stays the same while what it copies changes with a setting the menu does not show, the very
    complaint of 2026-09-26.
  - Keep two, renamed "Copy Prompt with Path" and "Copy Path Only": both visible, no setting, still two choices
    at every hand-off.
  - Holding ⌥ to turn one item into the other, the macOS way: Electron's menu items have no alternate items, so
    this needs native code.
  - Write "what the marks mean" once at the top of each session.md, so the prompt shrinks to its first line and
    the path alone is enough for any agent: one item, and a ZIP handed to an agent explains itself; but every
    session.md carries the legend, and old sessions keep an old one.
- **Decision needed:** Should the menu keep one copy item, the prompt with the path in it, with "path only" as a
  Settings choice that the menu label shows?
- **Verified:** read in the code; the copied prompt was produced by the app's own `promptFor` (probe output in
  the notes).
- **Owner's words:** "I just wonder whether we need just "Copy session info" when it comes with the prompt and
  everything, and in the settings you select whether you want to have the prompt with it or without it."
  — 2026-09-28. "The interface doesn't make sense. "Copy for AI," "Copy Paste," "Copy what?" It's not clear what's
  getting copied." — 2026-09-26. "One thing, actually, from the menu item: I want to be able to copy and paste the

## The keyboard (C17), keyboard and focus, platform conventions

### 4-10 · ⌘R in the editor wipes every mark without a word

- **Impact:** High — in the main scene the editor opens in front of the browser after every capture; ⌘R meant
  for Chrome (reload the build under review) lands in the editor, and every mark, reference and note on the
  screenshot disappears with no message. They can only be found again through Reopen Last Discarded, which the
  reviewer has no reason to look for.
- **Current experience:** Snapmark never sets its own app menu, so while an editor is in front, the menu bar holds
  Electron's stock menu, including "View → Reload ⌘R", "Force Reload ⇧⌘R" and "Toggle Developer Tools ⌥⌘I".
  ⌘R reloads the editor page: the screenshot comes back clean, the header and buttons look the same, and the old
  marks are filed under Discarded as "… · not saved". Tested: one box, one cross and reference 1 before; nothing
  after.
- **Visual:** `4-reload-annotated.png` (before and after, side by side).
- **Recommendation:** Give Snapmark its own app menu: Snapmark (About, Hide, Quit), Edit (Undo and Redo wired to
  the editor's own undo, Cut, Copy, Paste, Select All), Window (Minimize, Close). No Reload, Force Reload or
  Developer Tools in a release build.
- **Tradeoff:** A small menu to maintain; developer tools only in development builds.
- **Decision needed:** Should Snapmark ship its own app menu without Reload and Developer Tools?
- **Verified:** seen on screen (`4-reload-annotated.png`; probe: marks 1 → 0, Discarded 0 → 1, editor still
  open); Electron 44.4.5's default menu dumped with its accelerators.
- **Owner's words:** "I think another thing is, if I took a screenshot, annotated it, and discarded it, it is gone.
  I just wonder if we should introduce a shortcut with Escape and be able to recover it so nothing ever gets
  lost." — 2026-09-25

# Answers to the two questions

**Question 1 · New Session on ⌃⇧2.** A slip from ⌃⇧1 or ⌃⇧3 onto ⌃⇧2 costs, when the current session already has
screenshots: the capture that was meant (it never happens); a new session that silently becomes the destination
of every later capture and of Copy Prompt for AI; a way back only through Switch Session, told apart by the minute;
screenshots already added there cannot be moved; the empty session stays in the list. When the current session is
empty it costs only a notification and the lost capture. New Session does not need a global key: it happens once
per piece of work and has a menu item. Recommended: leave ⌃⇧2 unassigned as a buffer between the two captures,
New Session in the menu (optionally ⌃⇧N), plus a visible destination in the editor (4-02) and a way back from the
notification (4-03). Findings 4-01 to 4-04.

**Question 2 · one "Copy Session Info".** "Copy Prompt for AI" copies the quoted path to session.md, one line on
reading it, and a 12-line legend of the marks; "Copy session.md Path" copies the bare, unquoted path, which is the
first thing in the prompt already. One item is clearer, but "Session Info" is not: it names neither content and,
with a hidden Settings switch, its label would stay the same while its content changes. Recommended: one item
"Copy Prompt for AI" (sublabel "path + what the marks mean"), the path-only choice in Settings as the owner
proposes, and the menu label following that setting so the menu always says what it copies. Findings 4-05 to 4-09.

# Rule areas

### Keyboard and focus

- **Today:** Every Snapmark window takes focus when it opens (the editor after each capture, the session window,
  the area picker, the Keyboard Shortcuts window). A new reference moves the cursor into its note (verified); a new
  card starts in typing mode. Single-letter and digit keys are suspended in text fields; ⌘ keys always act,
  including the stock ⌘R. Esc steps back through four levels in the editor and ends by discarding; it cancels the
  area picker; it does nothing in the session window or the Keyboard Shortcuts window. Global keys: two captures
  and New Session on three adjacent digits. No keyboard route for moving marks or for any menu action; the key list
  lives three levels down and misses two windows.
- **Proposed default:**
  1. Global keys are for capturing only. Actions that change which session is current are menu actions; if one
     gets a key, it sits apart from the capture keys and can be undone.
  2. Esc steps back inside a surface and stops at its resting state; transient surfaces (area picker, Keyboard
     Shortcuts) close on Esc; discarding or closing a document is ⌘W.
  3. Letter and digit keys act only while no text field has the cursor; ⌘ keys act everywhere, and only keys the
     app defines itself are active (no stock Reload or developer tools).
  4. Every key is shown in one generated list, grouped by window and built from the keys actually registered, and
     that list is one key away (⌘/) from any Snapmark window.
  5. Every frequent pointer action has a key: arrow keys nudge the selected mark (⇧ for larger steps), Tab moves
     between marks.
- **Exceptions:** Placing a mark and dragging the area stay pointer actions (the job is pointing).
- **Findings:** 4-01, 4-10, 4-12, 4-14, 4-15, 4-17 to 4-19, 4-21 to 4-25, 4-64.

### Platform conventions

- **Today:** A menu bar app with Electron's stock app menu (File with only Close Window; View with Reload and
  Developer Tools; no Help; no Settings… ⌘,). The tray menu follows macOS Title Case and ellipsis rules; the
  editor's buttons use sentence case, the session window's Title Case, the Keyboard Shortcuts window sentence case.
  Key symbols: the app writes ⇧⌘Z in macOS order, the README writes ⌘⇧1. "Show Session in Finder" opens the folder
  instead of revealing it. Editor windows are all titled "Snapmark"; the session window "<name> — Snapmark".
  Relaunching the running app does nothing. ⌘Q asks before throwing away an unadded screenshot. Folder pickers
  explain themselves in a title macOS does not show and keep the default "Open" button.
- **Proposed default:**
  1. Snapmark's own app menu: Snapmark (About, Keyboard Shortcuts ⌘/, Hide, Quit), Edit wired to the editor's
     undo, Window, Help; no development items in release builds.
  2. Title Case for menu items, buttons and window titles; sentence case for descriptions, hints and
     notifications.
  3. Key symbols in the macOS order ⌃⌥⇧⌘, drawn in the system font.
  4. Window titles name the document first: "28 Sep 14:32 — Snapmark", "Screenshot 003 · 28 Sep 14:32 — Snapmark".
  5. "Show in Finder" reveals; "Open … Folder" opens. Ellipsis only when more input follows.
  6. Dialogs carry their explanation in the message and name their button after the action ("Use This Folder",
     "Reopen").
  7. Relaunching the running app opens its menu.
- **Exceptions:** The editor keeps single-key tools (a Figma-like canvas convention, the owner's request).
- **Findings:** 4-10 to 4-13, 4-20, 4-28, 4-42 to 4-44, 4-59, 4-64, 4-65.
